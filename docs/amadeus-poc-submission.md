# 아마데우스 (Amadeus) — PoC

> 러비더비의 현재/잠재 유저가 좋아할 만한 새로운 캐릭터 기반 서비스.
> 주제: **1. 캐릭터 기반 일상 / 생산성** — AI 페르소나를 PC 작업 공간으로 확장하는 Desktop Mate.

---

## 1. 유저와 기회 짚기

### 1-1. 어떤 유저인가요? 왜 이 유저를 타겟으로 설정하셨나요?

- **타겟 유저:** PC/노트북 앞에서 장시간 혼자 개인 작업(코딩, 학업, 업무 등)을 하며, 그 과정에서 **정서적 고립감과 감정적 교류의 결핍**을 느끼는 유저.

- **선정 이유 1 — 해결되지 않은 시장 공백:** 유저의 핵심 고통은 *작업 흐름을 깨지 않으면서* 외로움을 달래는 일이라고 생각합니다. 그런데 현재 시장에는 데스크톱 작업 맥락을 인지하여 **선제적으로 정서적 위로를 건네는** 서비스가 거의 없습니다. 기술은 충분히 발전했지만, 밤늦게 혼자 작업하는 유저의 고독을 채워주는 감성 영역은 비어 있습니다. 페인은 분명한데 공급이 없는 시장이라, 우선 공략할 유저로 정하였습니다.

- **선정 이유 2 — 기존 플랫폼의 제약:** 본 기획은 "기존 제타나 러비더비의 제약(앱/웹)을 PC로 확장할 수 있을까?"라는 질문에서 출발하였습니다. 모니터 앞에서 작업 흐름(Flow)을 깨지 않으면서 외로운 틈을 메워줄 동반자가 필요하다는 것을 가장 절실히 느꼈고, 가설을 직접 검증할 수 있는 유저라서 타겟으로 삼았습니다.

### 1-2. 충족되지 않은 니즈 / 페인 포인트

- **대화가 앱/웹 안에만 갇혀 있다 (플랫폼 확장성의 한계):** 제타·러비더비 같은 기존 서비스는 웹사이트가 있어도 결국 **그 앱/웹 안에서만 대화**가 가능합니다. 페르소나가 접근할 수 있는 건 채팅창에 내가 직접 작성한 말뿐이라, **나를 더 깊이 알거나 내 실제 하루를 함께할 방법이 없습니다.** 정작 유저가 가장 오래 머무는 PC 작업 공간으로는 관계가 전혀 확장되지 못합니다. 페르소나가 사용자의 전반적인 PC 작업을 인지하고 **오늘 하루를 함께 지냈다는 유대감**을 주려면 이 플랫폼 확장성 문제부터 풀어야 한다고 생각합니다.

- **작업 흐름을 깨지 않는 감정 교류의 부재:** 외로움을 달래려 모바일 앱을 켜 말을 걸거나 유튜브를 트는 순간, 하던 PC 작업의 흐름(Flow)은 그대로 끊깁니다. **결국 외로움을 푸는 비용이 집중력**인 셈입니다. 유저가 먼저 말을 거는 수고를 들이지 않더라도, 내 작업 환경을 알아서 인지하고 **조용히 곁을 지켜주는 동반자**가 없다는 것이 핵심 페인입니다. 즉 지금 시장에는 '능동적으로 다가오되 흐름은 깨지 않는' 비침범적 동반자가 비어 있습니다.

- **유저 컨텍스트가 디바이스 사이에서 통합되지 않는다 (Context 단절):** 모바일의 나와 PC 앞의 나는 같은 사람이지만, 두 환경이 분리돼 있어 AI(페르소나)는 나의 '현실 작업 상태'를 전혀 모릅니다. 모바일엔 감정·일상 대화가, PC엔 실제 작업 맥락이 따로 쌓일 뿐 하나로 합쳐지지 않습니다. 만약 **PC ↔ 모바일이 실시간 연동**된다면, AI(페르소나)는 *"낮에 모바일로 우울하다더니, 밤늦게까지 PC로 고생하고 있네"* 처럼 유저를 입체적으로 이해합니다. 이렇게 흩어진 맥락을 하나로 모을 때 비로소 **나를 더 잘 알고 더 깊이 말해주는 친밀감**이 완성되며, 이것이 유저가 가장 원하는 가치라고 생각합니다.

## 2. 서비스 기획

### 2-1. 가설 (Hypothesis)

- **배경:** 사람들은 혼자 PC 작업을 할 때 밀려오는 외로움을 달래려 유튜브를 틀거나 음악을 듣습니다. 하지만 이는 오히려 시각적·청각적 분산을 일으켜 작업의 흐름(Flow)을 흔듭니다. 게다가 나를 지켜봐 주거나 응원해 주는 **명확한 동기부여 요소가 없어** 작업을 오래 이어가지 못하고 중간에 멈추는 일이 잦으며, **외로움을 푸는 행위가 곧 집중을 깨는 행위가 되는 악순환**이 반복됩니다.

- **핵심 가설:** "**앱 안에서 텍스트로만 대화하는 챗봇을 넘어서자.** 유저의 실제 PC 작업 상황과 맥락을 인지하고, 기존 러비더비 모바일 데이터와 연동하는 **크로스 플랫폼 UX**를 구축한다면, 유저의 집중 흐름을 깨지 않으면서 외로움을 해소하고 **작업 지속 시간을 획기적으로 늘릴 수 있다.**"

### 2-2. 핵심 경험 (Core Experience)

유저가 아마데우스를 통해 얻을 가장 핵심적인 경험은 **"나보다 나를 더 잘 아는 입체적인 AI 동반자와의 크로스 플랫폼 여정"**입니다. 전체 스펙 중 다음 3가지 유기적 경험에 집중합니다.

1. **나를 완전하게 이해하는 AI:** 모바일에서 나눴던 일상 대화·성향·취향 데이터(메모리)에 더해, PC에서 내가 어떤 일(코딩, 학업, 업무 등)을 어떻게 하고 있는지까지 AI가 학습합니다. 그 결과 **세상에서 나를 가장 확실하게 아는 페르소나**를 마주하게 됩니다.

2. **끊김 없는 크로스 플랫폼 (Mobile ↔ Desktop):** 모바일 앱에만 머물던 러비더비 캐릭터가, 내가 PC를 켜는 순간 **데스크톱 메이트로 자연스럽게 이어집니다.** 디바이스의 경계를 넘어, 페르소나가 언제나 내 삶의 반경에 함께 있다는 감각을 선사합니다.

3. **흐름을 지켜주는 동기부여와 안식:** 딴짓을 하거나 지쳤을 때, 사각지대에서 넌지시 건네는 캐릭터의 한마디를 통해 **유튜브처럼 집중을 빼앗기지 않으면서도** 고독감을 풀고 작업을 끝까지 마칠 동기를 얻습니다.

> **가장 중요한 단일 경험:** 위 3가지가 하나로 모이는 지점은 **"짧은 NudgeNote → 사용자가 펼침 → 페르소나·메모리·맥락 기반 DeepChat"** 전환입니다. 작업 중에는 비침범적으로 다가가고, 사용자가 열었을 때만 깊어집니다. PoC는 이 전환 경험 하나를 증명하는 데 집중합니다.

### 2-3. 목표 (Success Metrics: 성공의 신호)

PoC 단계에 걸맞게 **유저의 행동 변화와 경험 만족도**에서 성공 신호를 찾습니다.

- **North Star — Nudge-to-DeepChat 전환율:** `DeepChat으로 이어진 NudgeNote 수 ÷ 전체 NudgeNote 수`. NudgeNote가 단순 알림이 아니라 **실제 대화 초대장**으로 작동했는지를 보여주는 핵심 지표입니다.
- **평균 작업 지속 시간(Focus Time) 증가:** 아마데우스 사용 전후, 유저가 작업을 중단하지 않고 유지하는 순수 집중 시간이 유의미하게 늘어나는가?
- **크로스 플랫폼 리텐션 동반 상승:** 데스크톱 아마데우스를 설치한 유저가 기존 러비더비 모바일 앱에 접속하는 빈도·체류 시간이 시너지로 함께 증가하는가?
- **"방해받지 않았다"는 피드백:** 유저 인터뷰에서 "캐릭터가 말을 걸었을 때 흐름이 깨지지 않고, 오히려 든든하고 위로가 됐다"는 긍정 UX 신호 확보.
- **"나를 정말 잘 안다"는 체감:** 모바일 데이터와 PC 작업 로그가 연동된 답변을 받았을 때 유저가 느끼는 친밀감·카타르시스 확인.

> **가드레일 지표:** NudgeNote가 방해로 느껴진 비율, 무시/거부 반응률이 일정 수준을 넘지 않아야 합니다. 비침범성이 깨지면 전환율이 높아도 실패로 봅니다.

## 3. PoC

### 3-1. 제작물

웹/모바일에서 만든 페르소나를 PC 작업 공간으로 끌어오는 **데스크톱 메이트 앱**을 실제 동작 수준으로 구현하였습니다.

- **데스크톱 앱:** Tauri 2 (Rust 백엔드) + React 19 / TypeScript 프론트엔드.
  - 우측 하단 Quiet Presence → NudgeNote → PocketChat → DeepChat → Daily Care Note 전체 플로우.
  - 트리거 엔진(작업 정체·장시간 집중·이탈 감지)은 **process-only 모드**로 동작합니다.
  - 트리거 엔진을 보강하기 위하여, 스크린 확인 및 Apple OCR로 사용자가 어떤 작업을 하는지 직접 인지합니다.
- **로컬 우선 데이터:** SQLite 기반 Local Timeline(발화/반응 이벤트, 원본 작업 로그). 민감 원본은 로컬에만 남깁니다.
- **클라우드 연동:** Supabase(Auth, `personas` 원본, `cloud_conversations`, cloud-safe 메모리 카드). 페르소나는 서버가 원본이고, 앱은 로컬 캐시로 보관합니다.
- **LLM:** 클라우드 LLM과 동일한 프롬프트 envelope를 쓰는 로컬 Qwen3-4B(llama sidecar)로 오프라인/프라이버시 경로를 확보합니다. *(로컬 추론 경로는 추후 예정)*
- **메모리 계층:** `local_private` / `syncable_summary` / `cloud_safe` 3계층으로 분리하여, Raw 데스크톱 맥락은 절대 클라우드로 보내지 않고 안전한 요약만 동기화합니다.

### 3-2. 핵심 인터랙션 (이 PoC에서 확인하려는 것)

1. **비침범적 능동 발화:** 트리거 발생 시 화면을 가리지 않는 1~2문장 NudgeNote가, 무시해도 괜찮은 톤으로 우측 하단에 조용히 뜹니다.

2. **단계적 친밀도(Context Hydration):** 사용자가 NudgeNote를 클릭하면 PocketChat으로, 직접 감정을 입력하면 DeepChat으로 전환되며 **그 깊이에 맞춰 맥락(작업 요약 → 메모리 → 관계성 → 페르소나/세계관)이 단계적으로 주입됩니다.**

3. **페르소나·맥락 반영 응답:** 동일 입력("과제하고 있는데 힘들어")에도 선택된 페르소나와 PC 작업 맥락에 따라 응답 톤이 달라집니다.

4. **하루를 함께한 감각(Daily Care Note):** 하루 끝에 점수표가 아닌 **정서적 회고 카드**를 제시합니다.

→ 이 PoC가 검증하려는 핵심 가설: **"짧게 다가가고, 열었을 때 깊어지는" 전환(Nudge→DeepChat)이 흐름을 깨지 않으면서 정서적 유대를 만듭니다.**

## 4. 본인의 판단

### 4-1. 작업에서 AI와 본인이 판단한 부분의 경계

> 작업 방식: 저는 방향·일관성 기준을 제시하고, AI가 초안·구조·코드를 먼저 만들었습니다. 저는 그것을 검토·수정하고 최종 결정을 내렸으며, 채택·폐기의 최종 판단 책임은 제게 있습니다.

| 영역 | AI 역할 | 내 역할 (최종 판단) |
| --- | --- | --- |
| 타겟 유저·핵심 경험 | 함께 상의하며 구체화·정리 | 거친 아이디어 제시 → 타겟·핵심경험 확정 |
| 아키텍처 | 구조 초안 먼저 설계 | **일관된 방향성 제시**(모듈 경계, `constants.ts` 등 패턴 통일) → 검토·최종 결정 |
| 코드 구현 | **코드 전부 작성** | 아키텍처 방향에 맞는지 검토·교정 지시 |
| 코드 품질·QA | **AI가 AI 결과를 검수**(리뷰·테스트) — Codex 코드 작성 → Claude QA | QA 루프 설계·기준 설정, 결과 확인 |
| UX·페르소나 응답 | NudgeNote·응답 톤 먼저 작성 | 방향 제시 → 취사선택·컷 |

### 4-2. 기획에서 자신 있는 포인트 / 더 검증이 필요한 부분

**제일 자신 있는 부분은 먼저 말을 거는 트리거라는 컨셉입니다.** AI(페르소나)가 적절한 순간 먼저 말을 걸어 동기부여를 주고, 그 메시지를 누르면 DeepChat으로 이어지는 흐름 — 이 **"비침범적 능동 발화 → 사용자가 열면 깊어짐"** 구조 자체는 일반 웹/앱 챗에서 자연스럽게 이어지는 검증된 패턴이라, 방향에는 확신이 있습니다.

**그리고 더 검증이 필요한 부분도 트리거입니다.** 정확히는 **언제** 발동시킬지의 메커니즘입니다. 현재는 OCR·스크린·프로세스 ID 등으로 점수를 매겨, 특정 점수를 넘으면 발동하는 방식입니다. 정책 4개를 두고 정책별 임계값을 달리해 적극적으로 말 거는 모드 / 덜 거는 모드를 나눴습니다. 하지만 *어떤 신호에 얼마의 가중치를 줘야 '방해'가 아닌 '적절한 순간'이 되는가*는 책상 위에서 정답을 내기 어렵습니다. 이 스코어 구조와 임계값은 실제 프로덕션 배포 후 사용자 피드백을 받아 지속적으로 보정하는 것이 맞다고 봅니다.
