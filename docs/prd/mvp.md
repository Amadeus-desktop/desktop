# [MVP] 아마데우스 (Amadeus)

> 조용하고 다정하게 곁에 있는 macOS 데스크톱 Active Companion

---

## 1. MVP 한 줄 정의

아마데우스 MVP는 macOS 데스크톱에서 사용자의 작업 흐름을 침범하지 않는 우측 하단 companion UI를 띄우고, 앱/창/idle 맥락과 제한적인 화면 인지 신호를 바탕으로 AI가 먼저 짧은 위로, 인정, 환기를 건네는 경험을 검증한다.

MVP는 생산성 비서나 작업 자동화 에이전트가 아니다. 사용자의 파일, 코드, 앱을 대신 조작하지 않는다.

---

## 2. 핵심 가설

### 2.1 제품 가설

사용자가 먼저 말을 걸지 않아도, 조용하고 다정한 companion이 적절한 타이밍에 말을 걸면 장시간 단독 작업의 고립감이 줄어든다.

### 2.2 UX 가설

능동 발화는 단순한 트리거 충족만으로 발생하면 방해나 감시처럼 느껴질 수 있다. 따라서 발화 전 별도의 발화 허용도 판단이 필요하다.

### 2.3 기술 가설

macOS의 앱/창 상태, idle 상태, 이벤트 기반 화면 캡처, 로컬 로그를 조합하면 상시 화면 감시 없이도 MVP 수준의 능동 발화 맥락을 만들 수 있다.

---

## 3. MVP 제품 원칙

### 3.1 기본 성격

MVP의 기본 캐릭터는 "조용하고 다정한 동반자"다.

- 짧게 말한다.
- 사용자를 평가하지 않는다.
- 명령하지 않는다.
- 생산성 압박을 주지 않는다.
- 딴짓을 지적하지 않는다.
- 무시당하면 조용해진다.
- 사용자가 클릭하거나 응답할 때만 대화 깊이를 늘린다.

장난기 있는 친구형 캐릭터와 집중 코치형 캐릭터는 MVP 이후 확장으로 둔다.

### 3.2 발화 원칙

- 하루 첫 발화는 Recognition 또는 Care 계열만 허용한다.
- Drift 발화는 첫 발화로 사용하지 않는다.
- 발화는 작은 말풍선으로 표시하고 자동으로 사라진다.
- 말풍선을 닫거나 무시하면 같은 유형의 발화를 일정 시간 반복하지 않는다.
- 전체화면, 회의, 영상 시청, 민감 앱/창에서는 발화를 억제한다.

## 4. 기술 스택

### 4.1 앱 스택

- Desktop Shell: Tauri
- Frontend: React, Vite, Tailwind CSS v4
- Package Manager: pnpm
- Backend: Rust
- OS Target: macOS 우선
- Local Database: SQLite
- ORM: Drizzle
- Default LLM: API provider
- Local LLM: llama.cpp sidecar

### 4.2 UI 기준

UI는 `templete.html`의 형식과 무드를 기준으로 맞춘다.

`templete.html`은 macOS glassmorphism 제어 센터 형식을 기준으로 한다. MVP UI는 이 파일의 반투명 윈도우, 좌측 사이드바, 탭 전환, 캐릭터 카드, iOS 스타일 토글, 인지 로그, 타임라인 형식을 React/Tailwind 컴포넌트로 재구성한다.

MVP에서 우측 하단 companion shell은 항상 작게 떠 있는 표면이고, 설정/권한/타임라인 확인은 `templete.html` 형식의 제어 센터 창에서 제공한다.

### 4.3 데이터 저장 기준

MVP의 이벤트, 발화, 사용자 반응, 타임라인 로그는 SQLite에 저장한다. TypeScript 영역에서 다루는 로컬 데이터 스키마와 마이그레이션은 Drizzle을 기준으로 구성한다.

Tauri의 React 프론트엔드는 Node 런타임이 아니므로 Node 전용 SQLite 드라이버에 의존하지 않는다. Drizzle은 schema, migration, 타입 기준의 source of truth로 사용하고, 실제 SQLite 파일 접근은 Rust backend의 Tauri command를 통해 수행한다.

```text
macOS Native Bridge
  -> Rust application service
  -> SQLite

Drizzle schema/migration
  -> SQLite schema 기준
  -> Frontend/Rust command contract 기준
```

## 5. MVP 기능 범위

### 5.1 Must Have

| 기능 | MVP 기준 |
| --- | --- |
| 우측 하단 companion shell | 화면 주요 작업 영역을 침범하지 않는 작은 상주 UI |
| 페이드인 말풍선 | 작은 발화가 조용히 나타났다가 사라짐 |
| 미니 채팅 | 말풍선 또는 캐릭터 클릭 시 대화 패널 열림 |
| 캐릭터 선택 | MVP에서는 최소 1종 캐릭터를 기본 제공 |
| 작업 타임라인 | 앱/창/트리거/발화/반응 로그 표시 |
| macOS 컨텍스트 | 활성 앱, 창 제목, 앱 전환, idle 상태 수집 |
| 개인정보 필터 | 민감 앱/창에서는 캡처와 발화 억제 |
| 권한 온보딩 | 화면 인지 권한과 저장하지 않는 정보를 명확히 안내 |
| 능동 발화 엔진 | Deep Pause, Milestone, Drift 후보 생성 |
| Speakability Score | 실제 발화 전 방해 가능성 판단 |
| LLM Provider Adapter | API provider와 Local llama.cpp provider 교체 구조 |

### 5.2 MVP 제외 범위

- 파일 이동, 코드 실행, 매크로 등 작업 대행
- 범용 생산성 비서 기능
- 복잡한 캐릭터 커스터마이징
- 장난기 있는 친구 모드
- 집중 코치 모드
- 음성 발화
- 모바일 연동
- 클라우드 상시 스크린샷 저장
- 온디바이스 비전 모델 최적화
- 일/주간 리포트 대시보드

## 6. 컨텍스트 수집 범위

### 6.1 상시 수집 신호

- 현재 활성 앱 이름
- 현재 활성 창 제목
- 앱 전환 시각
- 전면 앱 유지 시간
- 입력 활동 기반 idle 상태
- 업무 앱/비업무 앱 분류
- 최근 발화 시각
- 최근 사용자 반응

### 6.2 이벤트 기반 수집 신호

다음 조건에서만 화면 캡처 또는 비전 분석을 시도한다.

- 정체/멍 트리거 후보가 생긴 경우
- 장시간 업무 세션이 감지된 경우
- 업무 세션 중 비업무 앱 사용이 길어진 경우
- 사용자가 명시적으로 화면 인지를 허용한 경우
- 민감 앱/창 필터를 통과한 경우

### 6.3 저장하지 않는 정보

- 원본 스크린샷
- 키 입력 원문
- 파일/문서 원문
- 민감 창의 내용
- 브라우저 전체 방문 기록

## 7. 트리거 모델

### 7.1 Deep Pause Trigger

작업 중 멈춤 또는 정체 상태를 감지한다.

조건:

- 업무 앱이 전면에 있다.
- 같은 앱/창이 10분 이상 유지된다.
- 최근 2~5분간 입력이 거의 없다.
- 최근 30분 내 능동 발화가 없다.
- 전체화면, 회의, 영상, 민감 앱 상태가 아니다.

발화 예시:

> 잠깐 멈춘 것 같아서. 말 안 해도 괜찮아.

### 7.2 Milestone Trigger

장시간 집중 또는 업무 지속을 인정한다.

조건:

- 업무 앱 누적 사용 시간이 60/90/120분 기준점을 넘는다.
- 중간 이탈 시간이 짧다.
- 최근 발화가 없다.
- 사용자가 이전 격려 발화를 무시하거나 끄지 않았다.

발화 예시:

> 조용히 오래 해내고 있었네.

### 7.3 Drift Trigger

업무 세션 중 비업무 앱/사이트 사용이 길어진 상황을 감지한다.

조건:

- 업무 세션 중 비업무 앱/사이트로 전환된다.
- 비업무 상태가 10~20분 이상 지속된다.
- 사용자가 휴식 모드로 표시하지 않았다.
- 하루 Drift 발화 제한을 넘지 않았다.
- 최근 발화 무시 이력이 많지 않다.

발화 예시:

> 쉬는 중이면 괜찮아. 돌아가고 싶어지면 내가 옆에 있을게.

## 8. Speakability Score

트리거는 발화 후보를 만들 뿐이다. 실제 발화 여부는 Speakability Score로 결정한다.

```text
Speakability Score =
  상황 적합도
+ 마지막 발화 이후 경과 시간
+ 사용자 반응 이력
+ 현재 앱의 방해 민감도
+ 시간대/피로 맥락
- 최근 무시 횟수
- 전체화면/회의/영상 상태
- 민감 앱 여부
- 하루 발화 횟수 초과 여부
```

| 점수 | 행동 |
| --- | --- |
| 0~39 | 아무것도 하지 않음 |
| 40~59 | 캐릭터 상태만 미세하게 변경 |
| 60~79 | 작은 말풍선 표시 후 자동 사라짐 |
| 80~100 | 말풍선 표시, 클릭 시 대화 확장 |

## 9. LLM Provider 정책

MVP의 기본 발화 생성은 API provider로 시작한다. 단, 아키텍처는 provider 교체가 가능해야 한다.

```text
LLM Provider Adapter
  - ApiLlmProvider
  - LocalLlamaProvider
```

LocalLlamaProvider는 llama.cpp sidecar로 구동한다. MVP에서 Local LLM은 Must Have에 포함하지만, 품질 기준은 API와 동일한 품질이 아니라 "짧은 능동 발화와 기본 대화가 가능한 수준"으로 둔다.

Provider가 모두 실패하면 능동 발화는 중단하고 캐릭터 존재감만 유지한다.

## 10. 개인정보, 권한, 타임라인 원칙

### 10.1 권한 온보딩

화면 인지 권한은 기능 사용 전에 설명한다.

구체적인 화면 캡처/OCR 런타임 흐름과 권한 허용 UX는
[Screen Capture And OCR Runtime](../architecture/screen-capture-ocr-runtime.md)을 기준으로 한다.

- 어떤 정보를 보는지
- 언제 화면 캡처가 발생하는지
- 무엇을 저장하지 않는지
- 민감 앱/창을 어떻게 제외하는지
- 발화 근거를 어디서 확인할 수 있는지

### 10.2 개인정보 필터

기본 민감 범주:

- 비밀번호 관리자
- 은행/결제
- 메신저
- 이메일
- 의료/정부/인증 관련 창
- 사용자가 직접 추가한 앱/창 키워드

민감 앱/창에서는 화면 캡처와 비전 분석을 수행하지 않는다.

### 10.3 타임라인 저장 항목

- 시각
- 활성 앱 이름
- 창 제목 요약
- 트리거 유형
- 발화 여부
- 발화 문장
- 사용자 반응
- 화면 분석 여부
- 민감 필터 적용 여부

## 11. MVP 성공 기준

MVP 성공은 "많이 말하는 것"이 아니라 "말을 걸어도 불쾌하지 않은 것"으로 판단한다.

- 사용자가 먼저 입력하지 않아도 능동 발화가 발생한다.
- 능동 발화가 업무 앱/비업무 앱/idle 맥락에 따라 다르게 발생한다.
- 사용자가 발화 근거를 타임라인에서 확인할 수 있다.
- 민감 앱/창에서는 캡처와 발화가 억제된다.
- 발화 무시율이 높아지면 자동으로 조용해진다.
- API provider와 LocalLlamaProvider가 같은 인터페이스로 교체 가능하다.
- LocalLlamaProvider는 짧은 기본 발화를 생성할 수 있다.
