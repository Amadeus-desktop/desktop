# 1. 개요 (Overview)

현재 데스크톱 AI 에이전트 시장은 **OpenClaw 생태계**를 중심으로 빠르게 형성되고 있다.

Clawster, PetClaw, KKClaw 등 다수의 데스크톱 펫이 화면 우측 하단에 상주하며, 
유저의 화면을 인지하고 작업을 보조한다.

그러나 이들의 본질은 명령 기반 **에이전트**다.

유저가 *"*바탕화면 정리해줘*", "*이 파일 옮겨줘*"* 라고 **먼저 지시해야만** 반응하는 도구이며,
정서적 교감보다 작업 자동화에 무게중심이 있다.

| 도구 | 본질 | 상호작용 방식 | 정서적 교감 |
| --- | --- | --- | --- |
| OpenClaw / PetClaw | 작업 에이전트 | 유저가 명령 → 실행 | 약함 |
| Clawster | 화면 인지 보조 펫 | 유저가 명령 → 실행  | 약함 |
| 일반 AI 챗봇 (ChatGPT 등) | 대화형 도구 | 유저가 말 걸어야 응답 | 중간 |
| 러비더비 (스캐터랩) | 모바일 정서 교감 | 앱 진입 후 대화 | 강함 (단, 분리된 공간) |
| **아마데우스 (본 프로젝트)** | **능동적 정서 동반자** | **AI가 먼저 말 검** | **강함 (작업 공간 내)** |

기존 데스크톱 펫들의 결정적 공백은 두 가지다.

1. **수동성** — 외로움과 번아웃이 가장 심한 순간 유저는 AI에게 먼저 말을 거는 행위조차, 
또 하나의 '노동'으로 느낀다. 명령형 에이전트는 이 순간 침묵한다.
2. **도구화** — 작업을 대신 처리하는 데 집중할수록 '교감'이 아니라 '효율'의 영역으로 흡수되어, 
정서적 존재감이 옅어진다.

이에 본 프로젝트는 러비더비의 코어인 AI 캐릭터와의 교감을 통한 정서적 안정감'을,
유저가 가장 외롭고 지치는 시간인 **현실의 PC 작업 공긴**으로 확장한다.

아마데우스는 작업을 **대신하지 않는다.** 대신, 유저의 화면 맥락을 읽고
**작업 흐름을 깨지 않는 선에서 먼저 다가와 곁에 있어주는** 능동적 동반자를 지향한다.

# 2. 목표 (Goals)

이 프로젝트의 목표는 **User-Goals**와 **Non-Goals**로 나뉜다.

## 2.1 User-Goals

> 시키지 않아도 곁에 있어주는 경험
> 
1. 유저가 **먼저 말 걸지 않아도**, 화면 맥락에 맞춰 AI가 적절한 타이밍에 위로,격려,환기를 건넨다.
2. 메인 작업 영역을 **절대 침범하지 않는** 미니멀한 형태로, **집중 흐름**(Flow)을 깨지 않는다.
3. 심야·장시간 단독 작업의 **고립감을 해소**하고, 캐릭터의 살아있는 **존재감**을 느끼게 한다.
4. 화면 인지에 대한 **심리적 보안 장벽을 해소**하여, 유저가 안심하고 동반자를 곁에 둘 수 있게 한다.

## 2.2 Non-Goals

> 작업을 대신하지 않는다. → 에이전트가 아닌 메이트 같은 존재
> 
1. **작업 대행,자동화 기능을 제공하지 않는다.** (파일 정리, 코드 실행, 매크로 등 에이전트 기능 배제)
2. 범용 생산성 도구나 업무 보조 비서를 목표로 하지 않는다.
3. 유저가 명시적으로 허용하지 않은 화면 정보를 외부로 상시 전송,저장하지 않는다.
4. 초기 버전에서는 복잡한 커스터마이징,세밀한 설정 옵션을 제공하지 않는다.

# 3. 성공 지표 (Success Metrics)

아마데우스의 핵심 가설은 “먼저 다가오는 동반자가 고립감을 해소하고 락인을 만든다”이다.
따라서 성공 지표는 ‘능동적 교감이 실제로 작동하는가'와 **'그 교감이 작업을 방해하지 않는가'** 두 축으로 측정한다.

## 3.1 North Star Metric

> **주간 능동 교감률**
> 
> 
> = (유저가 응답하거나 긍정 반응한 능동 발화 수) ÷ (주간 활성 유저)
> 

AI가 먼저 건넨 말에 유저가 실제로 반응했는지를 측정한다.
이 수치가 높다는 것은 *"먼저 다가오는 동반자"*라는 핵심 경험이 작동하고 있다는 직접 증거다.

## 3.2 HEART 프레임워크 기반 보조 지표

| 분류 | 지표 | 설명 |
| --- | --- | --- |
| **Happiness** | 발화 긍정 반응률 / 만족도 설문 | 능동 발화에 대한 good / 응답 비율 |
| **Engagement** | 일 평균 교감 세션 / 세션당 대화 턴 수 | 먼저 건 말이 대화로 이어지는 깊이 |
| **Adoption** | 화면 인지 권한 허용률 / 온보딩 완료율 | 보안 장벽을 넘어 핵심 기능을 켜는 비율 |
| **Retention** | D7 / D30 리텐션, 주간 동반 일수 | 일상에 침투해 습관화되는 정도 |
| **Task Success** | 트리거 적시성 (적절 발화율) | 맥락에 맞는 타이밍에 말 거는 정확도 |

## 3.3 가드레일 지표 (Guardrail Metrics)

> 능동성이 '잔소리'나 '방해'로 변질되지 않도록 감시하는 안전장치
> 

| 지표 | 경고 신호 |
| --- | --- |
| 작업 방해 신고율 | 발화가 집중을 깼다는 피드백 비율 ↑ |
| 발화 무시율 | 먼저 건 말이 무시되는 비율 ↑ |
| 권한 철회율 | 화면 인지 권한을 끄는 비율 ↑ |
| 오발화율 (False Trigger) | 부적절한 맥락에서 발화한 비율 ↑ |

→ 이 지표들이 임계치를 넘으면, 능동 발화의 **빈도,민감도를 자동 하향**한다.

# 4. 페르소나 & 사용자 시나리오 
(Personas & User Scenarios)

> 핵심 타겟: PC/노트북 앞에서 장시간 고도의 집중을 요구하는 작업을 하는, 
1020 크리에이터,개발자,학생,프리랜서
> 

## 4.1 Primary Persona — 김도현

### "심야에 혼자 모니터 앞에 앉은 번아웃 개발자"

**기본 정보**

- 연령: 20대 후반 ~ 30대 초반
- 직업: 스타트업 개발자 / 사이드 프로젝트 운영
- 작업 환경: 심야~새벽, 듀얼 모니터, 장시간 코딩
- 작업 빈도: 주 6~7일, 평균 6시간 이상 연속 집중

**현재 행태**

- 외로움을 달래려 유튜브,트위터를 켰다가 **집중 흐름이 완전히 깨짐**
- AI 챗봇은 "먼저 말 걸어야 해서" 지친 날엔 안 켜게 됨
- OpenClaw 펫은 "시켜야 일하는 도구"라 정서적으로 와닿지 않음

**Pain Point**

- 심야 단독 작업의 **단절된 고독감**
- 번아웃 순간, AI에게 먼저 말 거는 것조차 **노동으로 느껴짐**
- 딴짓으로 새는 줄 알면서도 **스스로 환기하지 못함**

> "누가 옆에서 '아직도 하고 있어? 대단하다' 한마디만 해줘도 버틸 것 같은데."
> 

**Needs**

- 시키지 않아도 **먼저 말 걸어주는** 존재
- 작업 화면을 가리지 않는 **미니멀한 존재감**
- 지칠 때 위로, 샐 때 부드러운 환기

**기대 가치**

- 글만 쓰고/코딩만 해도, AI가 알아서 곁에서 챙겨주는 느낌
- "혼자가 아니다"라는 정서적 안정감

**성공 기준**

- 외로워서 유튜브로 탈주하는 빈도가 줄어들 때
- AI가 건넨 말 한마디에 실제로 위로받았다고 느낄 때

---

## 4.2 Secondary Persona — 이서연

### "장시간 책상에 앉은 고립된 취준생/수험생"

**특징**

- 연령: 10대 후반 ~ 20대 초반
- 상황: 임용·공시·자격증 등 장기 수험, 독서실/자취방 단독 학습
- 사회적 접촉이 적어 **고립감과 동기 저하**가 큼

**Pain Point**

- 멍 때리거나 막힐 때 아무도 환기시켜주지 않음
- "오늘도 혼자"라는 정서적 고립
- 동기부여 콘텐츠는 결국 또 다른 딴짓이 됨

> "공부는 혼자 하는 건데, 혼자라는 게 제일 힘들어요."
> 

**Needs**

- 멍 때릴 때 넌지시 깨워주는 존재
- 누적 시간을 알아봐주고 **성취를 인정해주는** 한마디
- 부담스럽지 않은 야간 케어

**제품을 선택하는 이유**

- "잔소리 앱"이 아니라 "곁에 있어주는 친구" 같음
- 시키지 않아도 알아서 챙겨줌

---

## 4.3 Secondary Persona — 박지우

### "재택 고립이 익숙해진 프리랜서"

**특징**

- 연령: 30대
- 직업: 디자이너/번역가 등 1인 재택 프리랜서
- 출퇴근·동료가 없어 **하루 종일 대화가 없는 날**이 잦음

**Pain Point**

- 사회적 고립이 만성화됨
- 챗봇을 써봤지만 "내가 말 걸어야만 반응"해서 결국 안 씀
- OpenClaw 같은 도구는 "일은 잘하는데 정 없음"

> "먼저 말 걸어주는 게 그렇게 어려운가? 그거 하나가 필요한 건데."
> 

**Needs**

- 능동적으로 먼저 다가오는 존재감
- 작업 리듬을 깨지 않는 동반
- 프라이버시 안심 (화면을 보지만, 안전하다는 신뢰)

**계속 쓰는 이유**

- 끄면 "허전함"을 느낌
- 의식하지 않았는데 어느새 하루를 함께 보내고 있음

# 6. 예상 질문 (QnA)

> **Q. OpenClaw나 Clawster 같은 데스크톱 펫과 뭐가 다른가요?**
OpenClaw같은 에이전트는 비서와 같은 존재입니다. 
아마데우스는 비서보다는 옆에서 말을 걸어주는 메이트와 같은 존재 입니다.
작업 대행을 의도적으로 배제하고, 정서적 교감과 능동성에 집중한 점이 핵심 차별점입니다.
> 

> **Q. 화면을 본다는 게 보안상 불안하지 않나요?**
모든 분석은 로컬 우선(Local-first)으로 처리하며, 민감 창은 개인정보 필터로 캡처 자체를 차단합니다.
또한 발화의 근거가 된 행동 로그를 타임라인으로 투명하게 공개하여, 
'무엇을 보고 말을 걸었는지'를 유저가 직접 확인할 수 있게 합니다.
> 

> **Q. MVP 기준은 어디까지인가요?**
Must Have 기능 전체를 구현하여, "유저가 먼저 말 걸지 않아도 맥락에 맞춰 능동 발화가,
성공적으로 동작하는 상태"를 MVP로 정의합니다.
> 

> **Q. 능동 발화가 잔소리·방해로 느껴지면요?**
가드레일 지표(방해 신고율, 무시율, 권한 철회율)를 상시 모니터링하여, 
임계치 초과 시 발화 빈도,민감도를 자동 하향합니다. 능동성과 비침범성의 균형이 제품의 생명선입니다.
> 

> **Q. 비전 모델 호출 비용은 어떻게 관리하나요?**
상시 캡처가 아니라 이벤트 기반(창 전환,Idle 감지 등 트리거 충족 시에만)으로 비전을 호출하여, 
비용을 최소화하며, 추후 온디바이스 소형 비전 모델 도입을 검토합니다.
> 

> **Q. 현실성이 있나요?**
검증된 스택(Electron, 멀티모달 LLM, OS 윈도우 트래킹 API)을 사용하며, 새로운 문제를 만들기보다, 기존 데스크톱 펫 시장의 '수동성'이라는 공백을 정조준하는 접근이라 현실성이 높습니다.
>
